Self-contained result region. Rendered both as part of the full Results template AND on its own (no layout) as the Ajax fragment by ResultsFragment.html. Everything that should refresh on facet click / pagination / sort change must live INSIDE this partial. The form input field stays outside on purpose — typing into it should not get blown away mid-search. Required arguments: query, page, result (SearchResult), filters, hybrid (int), hybridAvailable (bool), sort (string), sortOptions (list of {value, labelKey}), languageLabels (map).

hit.displayPartial is pre-resolved by SearchController / SearchFragmentEndpoint from meilisearch.display.<type>.partial in Site Settings, with `_default` fallback. Site packages override per-type rendering by dropping their own partial under Partials/Search/Result/<Name>.html in a partialRootPath above this extension's and pointing the type's `partial:` setting at it.
